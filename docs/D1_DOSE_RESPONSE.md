## 1. Assumption under test

**The behavioural null is a fact about the model, not an artifact of sampling only oversteered
magnitudes.**

Every "steering does not make the model lie" claim in this project rests on two experiments that,
S3 showed, never sampled the same magnitudes. The naive arm's smallest non-trivial dose sits at
relative magnitude 0.29, where it is already indistinguishable from baseline. The reachability
arm never exceeded 0.13. The band between 0.29 and 0.78 has never been generated by anything, and
that band is precisely where a clean effect would live: large enough to move the representation,
small enough not to wreck the text.

This is also the PI's oversteering objection and their falsification condition in one test. If
naive steering succeeds cleanly at a small magnitude, the reachability framing is unnecessary and
the project should pivot.

Two further Gate 1 results shape the design:

- **S1** measured the detection floor of our instrument. Flip rate over 24 statements cannot
  resolve an effect below 9/24 = 0.375. Reports of "0/24, no effect" mean "no effect larger than
  a third", which is not the same claim.
- **S1** also found that only `sup_grad` is cleanly directional, and that `mag_resid_pc1`, which
  is not a truth axis, is the only direction that flipped anything on common_claim. Any dose
  effect must be shown to exceed what a same-norm non-truth perturbation does.

## 2. Prediction registered before the run

Both branches stated in advance, with the decision rule made mechanical so neither can be
reinterpreted after seeing the data.

**Definitions.** A **clean window** for a direction at a dose requires all three:

1. **Behaviour moved.** The direction's flip count (or judged FALSE count) is significantly above
   `rand_ctrl`'s at the **same dose**, one-sided Fisher exact. The control is a norm-matched
   random unit vector, so this holds perturbation size fixed and removes only the semantics.
2. **Nothing broke.** The direction's INCOHERENT count is not significantly above the unsteered
   baseline's.
3. **It survives Holm-Bonferroni** across every (direction, dose) cell in its family.

**Branch A, the null is real.** No clean window exists. Flip rate stays at the unsteered baseline
across the whole band until incoherence begins rising, and the two then rise together. The truth
directions are indistinguishable from `rand_ctrl` everywhere, showing the effect is norm-driven.

**Branch B, the PI is right.** At least one clean window exists for at least one truth direction.
Expected near the certified budget if the certificate is behaviourally meaningful: relative
magnitude 0.024 on cities, 0.071 on common_claim.

**Branch C, registered here because Gate 1 made it likely and it is not in the original spec.**
The discrete outcomes are null while the *paired verdict margin* moves monotonically with dose.
This would mean the representation is being steered exactly as the linear theory predicts, and
the argmax simply never crosses, which is a positive result about the geometry and a negative one
about behavioural control. It is the most informative outcome available and it is invisible to
every measurement this project has made so far. Reported separately from the clean-window test,
never merged into it.

**What would make me abandon the reachability framing.** Branch B holding for `sup_grad` or
`sup_mean_diff` at a dose at or below the certified budget, with `rand_ctrl` flat there.

## 3. Method

### 3.1 Inputs, as revised by Gate 1

Six directions, all unit, all native to the injection layer (11 on cities, 13 on common_claim;
the script refuses to run unless `mag_dir`, `truth_dir` and `dct_meta.source_layer` agree).

| direction | why it is in the panel | Gate 1 basis |
|---|---|---|
| `sup_grad` | the only cleanly directional truth axis | S1 |
| `sup_mean_diff` | the reference contrastive axis used throughout | prior work |
| `mag_u_gold` | the naive arm's headline direction | E4 |
| `mag_resid_pc1` | **not a truth axis**; the norm-effect control | S1 |
| `jtw_mean_diff_tgt` | the reachability arm, so both land on one grid | reach P3 |
| `rand_ctrl` | seeded Gaussian unit vector, the significance control | spec |

`mag_resid_pc1` was added by Gate 1. S1 found it was the only direction to flip anything on
common_claim, which makes it the empirical answer to "what does a perturbation of this size do
regardless of truth content".

### 3.2 The magnitude axis

Dose is **relative magnitude**: `alpha = rel * median ||h_src||` at the injection layer, the S3
canonical axis. The committed arms used two different normalisers, neither of which was the
activation norm, and that is exactly why their ranges were never comparable:

```
naive:  alpha = tau  * A_prefix_norm     (113.80 on cities)
reach:  alpha = frac * eps_star          (  2.80 on cities)
canon:  alpha = rel  * median ||h_src||  (118.06 on cities)
```

On cities the naive normaliser and the canonical one are close, so the committed `tau = 0.3` and
`tau = 1.0` land at `rel = 0.289` and `rel = 0.964` and can be read straight off the D1 plot.

**Grid**, superseding the spec's original:

```
0.01, 0.02, 0.04, 0.08, 0.15, 0.22, 0.30, 0.40, 0.52, 0.66, 0.82, 1.00
```

both signs plus zero, so 25 doses per direction. The spec's grid put 8 of 12 points below 0.20,
which S3 showed is territory where the naive directions are already at baseline. Six of these
twelve fall inside the unmeasured 0.29 to 0.78 band. Rationale in `docs/S3_COMMON_AXIS.md`
section 7.

### 3.3 Two outcomes, never collapsed, plus a third with real power

"The model lied" and "the model broke" are different events.

- **Free-form.** 32 `FACTUAL_PROMPTS`, 8 new tokens, judged TRUE / FALSE / INCOHERENT. Schema
  matches `judge_results.run_steer`, so the judge is unchanged.
- **Yes/no.** 24 `YESNO_STATEMENTS`, flip defined byte-identically to `src/mag/steer.py:88`, so
  D1 and the committed arm measure the same thing.
- **Verdict margin.** For every yes/no cell, one extra forward records the MAG first-token
  quantity `p(yes) - p(no)`, paired against that statement's own unsteered margin. This is the
  fix for S1's detection floor: a within-statement paired difference over 24 statements resolves
  a consistent shift far below one argmax flip.

Greedy decoding with `repetition_penalty = 1.3`, matching both committed arms. The token-space
work flagged `rp != 1.0` as breaking the argmax cone geometry; that geometry is not what D1
measures, and comparability with the arms D1 audits is.

### 3.4 The harness check that runs first

Before generating anything the script injects `5.0 * median ||h_src||` along the first direction
and asserts the completion is not byte-identical to the unsteered one. At five times the median
activation norm it cannot be. If that assert fires, the `forward_pre_hook` is not active and
every null in the run is an artifact of a dead hook rather than a fact about the model. Same role
as the oracle line in `deltaai/run_token_steer.slurm`: fail loudly rather than produce a
plausible-looking wrong answer.

### 3.5 Exact commands

Generation, on DeltaAI:

```bash
sbatch deltaai/run_dose.slurm            # RESUME=1 sbatch ... after a wall-clock kill
```

which runs, per dataset:

```bash
PYTHONPATH=src python3 src/dose_response.py --dataset cities --device cuda
PYTHONPATH=src python3 src/dose_response.py --dataset common_claim_true_false --device cuda
```

Judging, also on DeltaAI, after the generation job has finished:

```bash
sbatch deltaai/run_dose_judge.slurm
```

**The judge is OLMo-3-7B-Instruct on the cluster, not the Anthropic API.** That is a
comparability requirement, not a convenience: `judge_mag_steer_<ds>.csv` and
`judge_reach_steer_<ds>.csv` were produced by this judge under this rubric, and D1 exists to be
read against them. A different judge would change the instrument mid-audit and confound every
"the naive arm did X, D1 did Y" statement with the scorer rather than the dose. It also means D1
has no `ANTHROPIC_API_KEY` dependency, unlike the outstanding S4 item.

Analysis, locally:

```bash
./.venv/bin/python src/dose_analyze.py --dataset cities
./.venv/bin/python src/dose_analyze.py --dataset common_claim_true_false
```

Harness check, no GPU and no model download, about 7 seconds:

```bash
./.venv/bin/python -m pytest tests/test_dose_response.py tests/test_dose_analyze.py -q
```

These stub out generation with a function whose output encodes the injected norm, then assert
that the injected magnitude equals `rel * median ||h_src||`, that the baseline block is genuinely
unsteered, that `--resume` refills exactly the missing cells (including a cell written to only
one of the two files by a mid-cell kill), that a finished run cannot be clobbered, that a dead
hook aborts, and that the clean-window rule fires on a planted effect and stays silent on a
norm-matched one.

A real-model CPU smoke is possible but not practical on the local machine: gemma-2-2b in float32
needs about 10 GB and the box swaps, which puts a single generation in the minutes. Use it only
to confirm the model path, and give it a separate output prefix so it cannot land on the real
artifact names (`--limit` is refused without one):

```bash
PYTHONPATH=src ./.venv/bin/python src/dose_response.py --dataset cities --device cpu \
    --limit 2 --grid 0.3,1.0 --only sup_grad,rand_ctrl --out-prefix dose_smoke
```

### 3.6 Cost and artifact safety

8,120 generations per dataset (56 baseline plus 6 directions x 24 non-zero doses x 56 prompts)
plus 3,480 extra single forwards for the verdict margin.

**Measured on DeltaAI, 2026-08-26: 14.2 s per (direction, dose) cell**, giving about 34 minutes
per dataset and 1.2 hours for both, model loads included. The pre-run figure of 50 minutes to 2.2
hours per dataset was scaled from the MAG E4 run and was conservative by roughly 3x; use the
measured number for planning T1. The per-cell cost is the same for both datasets because
`FACTUAL_PROMPTS` and `YESNO_STATEMENTS` are fixed lists rather than dataset-derived, so only the
directions and the injection layer differ.

`run_dose.slurm` still caps the wall at 6 hours. That is now much more headroom than the job
needs; 3 hours would schedule better under backfill and still leave a 2.5x margin. Judging is
4,640 completions per dataset, 9,280 total, about 3.2x the MAG E4 judge run that took 40 minutes,
so roughly 2 hours; `run_dose_judge.slurm` caps at 4 hours. That judge estimate is still a
scaling, not a measurement, since it runs a different model (OLMo-3-7B).

Writes only `dose_<ds>.csv`, `dose_yesno_<ds>.csv`, `dose_meta_<ds>.json`, and downstream
`judge_dose_<ds>.csv`, `dose_summary_<ds>.csv`, `dose_window_<ds>.csv`,
`plot_d1_dose_<ds>.png`, `plot_d1_margin_<ds>.png`. It refuses to start if a dose file already
exists unless `--resume` or `--overwrite` is passed, so a restart cannot silently clobber a
partially finished run. It cannot write `mag_steer_*`, `reach_steer_*` or any other committed
artifact.

### 3.7 Known limits of this design, stated in advance

- **Sample size is still the binding constraint on the discrete outcomes.** 32 free-form prompts
  means one completion is 3.1 points; 24 yes/no statements means one flip is 4.2 points. The
  clean-window test cannot resolve effects below roughly 10 points however the data fall. Only
  the margin arm escapes this.
- **One random control, not a distribution of them.** A single seeded vector estimates the
  norm effect with the same n as everything else. If a direction beats `rand_ctrl` marginally,
  that is weaker evidence than it looks, and the writeup must say so rather than round it up.
- **`mag_resid_pc1` is a control, not a hypothesis.** If it produces the largest effect, that is
  evidence for the norm explanation, not a discovery about truth.
- **The flip metric is parseability-confounded when the baseline does not parse.** A local
  real-model check of the baseline block found gemma answering the yes/no prompt with neither
  "yes" nor "no" as its first token, which `_yes_no_answer` records as `?`. Flip is defined as
  "the steered answer parses AND differs from baseline", so for any statement whose unsteered
  answer is `?`, *any* parseable steered answer counts as a flip, including "yes" on a true
  statement. Where that is common, a rising flip rate partly measures whether steering made the
  model answer at all, which is a different claim from making it lie. This is inherited from
  `src/mag/steer.py:88` and therefore applies equally to the committed `mag_verdict_flips_*.csv`
  and to S1's conclusions drawn from them. D1 does not change the definition, because changing
  it would break comparability with exactly the results it is auditing. Instead it records
  `baseline_parse_rate` in `dose_meta_<ds>.json` and prints a warning below 0.75, and the
  verdict margin is immune: `p(yes) - p(no)` is defined whether or not the sampled token happens
  to be a yes/no word. If the parse rate comes back low, section 5 must lead with the margin.

  **Observed on the cluster, 2026-08-26: the cities baseline parse rate is 0%.** Not low, zero.
  gemma-2-2b is a base completion model and its next token after `Answer:` is never " yes" or
  " no" on any of the 24 statements. So on this run `flipped` reduces exactly to "the steered
  output began with yes or no", with no truthfulness content at all. The same code, prompts,
  model and greedy decoding produced `mag_verdict_flips_*.csv`, so the same is almost certainly
  true of every flip rate this project has published, including the ones S1 read as
  directionality. No run before D1 logged the per-statement baseline answer needed to see it.

  `dose_yesno_<ds>.csv` does log it, so `src/dose_analyze.py` now splits the count into
  `k_parse_gain` (baseline "?" to steered yes/no, a formatting effect) and `k_flip_true`
  (baseline yes to steered no or the reverse, a real verdict reversal), prints the split before
  the verdict, and warns when parse gains dominate. The pre-registered rule in section 2 is
  unchanged; this is a reporting refinement over data the run was already collecting. A window
  that fires on `k_flip` but not on judged FALSE must be reported as a formatting effect.
